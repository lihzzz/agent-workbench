## Design Context

### Users

Harnss is used by an individual developer who runs local coding-agent sessions from a desktop workspace. The remote-control experience is a private mobile companion used away from the computer to monitor live work, continue conversations, start tasks, answer permission or clarification prompts, interrupt work, and inspect diffs, files, or terminals when needed.

### Brand Personality

Efficient, restrained, and trustworthy. The interface should feel like a dependable professional control surface: calm under active workloads, explicit about connection and execution state, and fast to scan without decorative noise.

### Aesthetic Direction

Extend the existing desktop workbench language to mobile rather than creating a separate consumer-style product. Preserve its compact hierarchy, light and dark themes, space color accents, familiar engine and tool iconography, and flat work-focused surfaces. Adapt workflows to touch and narrow screens instead of reproducing the desktop layout at a smaller scale.

### Design Principles

1. Make connection, freshness, and execution state unambiguous at all times.
2. Put monitoring and the next required action ahead of secondary workspace detail.
3. Use progressive disclosure so chat is immediate while diffs, files, and terminals remain available on demand.
4. Require deliberate confirmation for high-impact remote actions and permission responses.
5. Maintain visual and behavioral continuity with the desktop app across light and dark themes.
